## Design Specificity Verdict

**具体于数据模型，尚未具体于任务。**

列与文案是明确的 DSH 的：技能 / 来源（内置 vs 本机）、调用次数拆成 模型/用户（`skill` 工具路径 vs `/skill-name` 注入路径）、会话数、把「已卸载/未知」作为一等桶钉在顶部、以及「统计口径」主动交代"计的是尝试不是成功""删会话就删用量"。`sourceLabel()` 里那条"source 为空 = 从本机技能根目录发现"的规则，是只有这个产品才需要做的决定。

但 KPI 条 + 卡片 + 工具栏 + 表格这个外壳、0.5px 发丝网格、等宽数字，可以整块搬到任何"带计数的列表"面板上而一个像素不改。结论：**它是为本产品的数据结构写的，还不是为本产品的任务写的。** 那个任务 —— "这个技能还该留着吗" —— 没有任何专门的affordance：没有来源筛选、没有排序控件、没有"陈旧"视图、也没法把那 72 个未用技能带走。

一处具体的特异性泄漏：`sourceLabel()` 只翻译了 DSH 六个 source 桶里的两个，`project-dsh` / `project-agents` / `runtime` / `custom` 会在中文界面里原样打印英文 kebab-case —— 而 `project-*` 恰恰是"cwd 在这里很重要"的那个情形。

**确定性扫描**：`impeccable detect --json` 对目录与单文件两次运行均输出 `[]`、退出 0，零发现。这个 `[]` 经对照实验确认为**真阴性**而非"跳过不支持的文件类型"：规则引擎有效（注入 `bad.css` → 3 条 `overused-font`/`gradient-text`/`bounce-easing`）；检测器确实会走 `.js` 的正则路径（在副本尾部追加 `.mock{font-family:Inter;-webkit-background-clip:text}` → 2 条，定位到第 835 行）；无任何抑制来源（无 `.impeccable/`、无 config、文件内 0 个 `impeccable-disable`）。

**但这个通过毫无意义**：对照 `control.css`（含 `outline:none`、`font-size:7px`、`color:#999` on `#aaa`、`transition:all`）同样返回 `[]` 退出 0 —— 描边移除、不可读字号、对比度**完全不在规则集内**。零发现不等于界面干净，尤其不能用来为下面那条对比度问题背书。

**视觉浮层：不可用。** 本会话没有浏览器自动化工具，真实 Electron 应用无法注入脚本，未做尝试，也不声称成功。替代证据为无头 Chrome + 预览台（驱动真实 `client.js` + 真实主题 CSS），并额外用一次性 CDP 采集了计算样式与 AX 树。

## Overall Impression

一个把"可信"这件事做对了的只读面板：自报误差、零值自我抑制、发丝网格、行高一致、等宽数字对齐右边缘。最大的机会是**把层次指向可行动的轴** —— 页面最大的字（22px/600）是 80/8/12，回答"有多少"；而回答面板存在理由的 调用次数 是 13px 加一根 ≤86px 的条，压在第 340px 往下。视觉峰值不是行动轴。

## What's Working

1. **占比条复述数字而不是替代它**（`.ui-calls-wrap`/`.ui-calls-bar`，opacity .26），因此在灰度、低视力、读屏下都成立；且分母 `peakCalls` 取自 `allRows`（全目录）而非筛选后的 `rows` —— 输入筛选**不会**重新缩放所有条、静默谎报相对量级。多数仪表盘做错这一点，这里把理由写进了注释。
2. **会自我报告误差、但懂得让开**：`tracked` footer（扫描会话数 / 不可读会话 / 无法解析事件）+ 折叠的「统计口径」（计尝试不计成功、删会话即删用量、目录是跨工作区并集）意味着一个错数字能指向自己的成因，而它被设在 11px 三级色、默认折叠，永不与答案竞争。配合零值孤儿格的自我抑制（flex 条吸收空位，而不是固定四列 grid 留个洞），这是一个只在该出声时出声的面板。DESIGN 里显式记录了那次 CLS 取舍。
3. **让整列可扫读的表格纪律**：`table-layout: fixed` + 显式 `th` 宽度 + 描述行恒以 `min-height:16px` 渲染 → 每一行等高；mono + `tabular-nums` → 每个数字共享右边缘，眼睛可以沿 调用次数 直下而不必重新定位。粘性表头是靠**刻意不套 `overflow-x` 容器**换来的，代价付在窄屏上（按优先级丢列），而不是悄悄弄坏粘性轴或塞一个横向滚动条进卡片 —— 这是一次诚实的权衡。

## Priority Issues

**无 P0**：在我能构造出的所有状态下，面板都能完成主任务。3 个 P1、2 个 P2。

### [P1] 警告 token 不存在，导致两处警告都失效

`client.js:282`（`.ui-badge-warn`，已卸载行徽章）与 `client.js:321`（`.ui-warn`，「技能目录可能不完整」横幅）使用 `--dsw-alias-state-warning-primary`。主题定义的是 `--dsw-alias-state-warn-primary`（amber-500），**不存在任何 `…-warning-…` 名字**。两处都静默走了 fallback。我自己逐 token 对照主题复核过：文件里 14 个 alias token 中 13 个命中，唯独这个名字 MISS。

后果：被刻意钉在顶部以便行动的那一行，其徽章与中性的 仅模型/仅用户 徽章视觉完全相同；而同一概念在往上两条带的 KPI 条里是琥珀色。更糟的是，在数据最不可信的那一刻，警告横幅退化成一个普通发丝框。**注意这个不一致是我自己造成的** —— `is-alert`（第 193 行）用的是正确名字，另两处是错的。

修：两处改名，并加一条校验（client.js 里每个 `--dsw-alias-*` 都必须在主题里解析得到）。对应命令 `harden`。

### [P1] 侧栏展开时 最近使用 会溢出列宽

`.ui-table td.ui-col-last{white-space:nowrap}` + `table-layout:fixed` + 13% 列宽 + 断点全部 key 在**视口**上而非面板上。我实测复核了这条算术：

```
表宽 1107px -> 最近使用列 144px -> 可用内容 124px  OK
表宽  905px -> 最近使用列 118px -> 可用内容  98px  溢出(需要 ~104px)
表宽  700px -> 最近使用列  91px -> 可用内容  71px  溢出(需要 ~104px)
```

905px 正是「1215 窗口 − 约 310 侧栏」的常见形态。而且 ≤900px 断点触发后**依然是坏的** —— 13% 在收缩的表上永远给不出 104px。因为粘性表头不允许 `overflow-x` 容器，没有任何东西吸收它。坏的这一列恰好是 最近使用，即"这个技能还活着吗"的后半句。

修：给这一列真正的 `min-width` 下限而不是百分比；把无年份的绝对时间戳换成相对形式（"3 天前"，也正是问题本身在问的）；去掉该单元格的 `nowrap` 让它退化成两行而不是压到邻列；断点改为针对面板自身宽度的 `@container`。对应命令 `adapt`。

### [P1] 浅色主题对比度地板：面板大部分文字低于 AA

`--dsw-alias-label-tertiary` = `#81858c` 落在 `#ffffff` 上 = **3.71:1**，而它被用在 **11px** 上：表格列头、全部 KPI 标签与副行、来源列、每条技能描述、整个 footer。B 用 CDP 实测出 **14 个文字组**命中该值（16 进制手算复核一致：3.71）。`label-secondary` = `#61666b` = 5.8:1 可用且已用于数字单元格。**深色主题 0 个元素低于阈值**（暗色三级色 8.54:1），所以这是纯浅色问题。

归属要说清楚：client.js 只**引用** token，从不定义 16 进制，失败值继承自宿主主题。修法在 token 的用法，不是在自己的调色板。面板里最小的字就是对比度最低的字，而它承载着区分两个相似技能名所需的描述。

修：11–12px 且必须被阅读的一律换 `label-secondary`；tertiary 只留给真正可丢弃的文字（免责声明、"退到背景"正是目的的零值格）；不要再把 11px 用在需要读而非扫的文字上。对应命令 `typeset`。

### [P2] 近 30 天 列当前每行都是「1 天」/「2 天」，含义藏在 tooltip 里

迷你条形分支只在活跃天数 ≥4 时才渲染；实测数据里 8 个被用过的技能全部 ≤2，所以 100% 的单元格走的是统计分支。紧挨着一个显示真实日期的 最近使用 列，"2 天"读起来就是个日期。完整句子（"近 30 天里有 N 天发生调用"）只作为 `title`/`aria-label` 存在。该列占掉本就紧张的 10% 宽度，而它为之而建的 30 根条形图对这个受众的数据**永远不会出现**。

修：让单元格自解释且紧凑（"30天内 2 天"，或直接换成相对时间形式）；按内容定宽而不是按百分比；如果 30 根条形在真实数据上不可能出现，就删掉那条分支。对应命令 `clarify`。

### [P2] 面板点出了未使用的技能，却不给用户任何后续动作

只读是对的、超出范围不改，但那 72 行藏在工具栏最右侧的复选框后面（默认关、`margin-left:auto`、每次重挂重置），未用数量需要读者自己算（80 − 8），没有按来源筛选、没有排序控件、也没法复制这份清单。面板存在的全部理由是"哪些技能还值得留"，而它给出的答案是一个要用户自己推导的数字，加一份要从截断表格里手抄的清单。洞察被交付，然后被丢下。

修：当 >0 时把该计数升格为自己的 KPI 格（"从未使用 72"，复用孤儿格已有的条件渲染模式）；把开关移到筛选旁边并做成三态（全部 / 用过的 / 从未使用）；两者都持久化；对筛选集加一键"复制这些技能名"，以及在宿主允许时深链到技能根目录。对应命令 `shape`。

## Persona Red Flags

**Alex（高效用户）** —— 没有聚焦筛选的快捷键、没有 Esc 清空、没有刷新快捷键；**表格行完全不可聚焦**，键盘优先的用户连落到一行上去看被截断的描述都做不到；排序写死，所以他最自然的动作（按 最近使用 升序找出死技能）不可能完成；没有来源筛选，尽管 内置 vs 本机 正是"我能安全删掉什么"所依赖的轴；「显示未使用的技能」每次重挂都重置，他唯一想要的那个视图每次访问都要重新打开；没有批量/多选、没有复制，提取 72 个名字等于从省略号表格里手抄；任何地方都没有相对的数据新鲜度，所以盯着实时会话的用户看着陈旧数字却无从判断多陈旧。

**Sam（无障碍依赖）** —— 浅色主题下表格列头、KPI 标签、描述、来源列、footer 全是 11px / 3.71:1；截断描述的**唯一**全文路径是一个不可聚焦 `div` 上的 `title`，所以纯键盘或 200% 缩放的用户打不开它；搜索框唯一的标签就是 placeholder（`aria-label` 复述了它，连省略号一起），没有常驻可见标签；没有 `aria-sort`、没有排序指示器，排序从不被播报；`role="status"` 只存在于首次绘制前那个框上，它第一次绘制后就离开 DOM，于是 刷新 会静默替换每一个 KPI，而 KPI 条和表格周围没有 `aria-live`；只靠 `title` 的趋势单元格被播报为光秃秃的"1 天"；200% 缩放的窄窗口下 ≤680px 断点会**静默移除两列数据**，既不提示也无法找回。

**Riley（刻意施压者）** —— 空状态撞车是他的第一发现：空筛选、空目录、未跑完的扫描渲染出**同一个**「没有匹配的技能。」框，所以冷缓存的全新安装看起来像坏了（KPI 全零 + 空框 + "最后扫描 —"）；孤儿 KPI 格的出现/消失会改变另三格的宽度（flex `1 1 0`），于是数字 80 在不同日子坐在不同位置；面板从不报告自己是哪个构建，所以"为什么我这儿显示 `bundled` 而源码里是 内置"无法从界面诊断 —— **而这正是当前运行中的应用所处的状态**；删除一个会话会静默下调历史计数；长技能名会折行（`.ui-skill-name` 没有 `nowrap`/`overflow:hidden`，`.ui-skill` 有 `min-width:0`），重新破坏设计刚为描述修好的行高节奏 —— 今天的名字长度下是潜伏的，某个长度下必然发生；700 字的 ponytail 描述带着字面量尾部 `\n` 到达，在原生 tooltip 里渲染成一堵墙；筛选没有防抖、表格没有虚拟化（今天 80 行 × 最多 30 根条 = 2400 个节点），技能数以百计后每次按键都会重渲 tbody。（不选 Jordan：这个面板的受众已经知道技能是什么，且文案正确地假定了这一点。）

## Minor Observations

- **先记核验，不是设计**：运行中的面板是 `bundled` + `—` + 一个零值孤儿格；源码产出的是 内置/本机 且不含那格。**正在跑的 bundle 比被审的文件旧**，而界面任何地方都不暴露构建标识（`BUILD='skill-insights-2'` 被导出却从未渲染）。建议把构建串渲染在「统计口径」旁边，让这种不一致自证。
- `--si-fs-md: 14px` 被声明却从未使用，而 `.ui-title` 硬编码 `18px` —— 这是文件自己"固定五级阶梯、绝不临时定字号"主张之外的第 6 个尺寸，也是 CSS 里唯一硬编码的 `font-size`。
- 模型/用户 列 8 行全是 `N / 0`（23 个会话里 0 次用户调用），与 会话数 合计占掉 15% 宽度去复述常量。当 `totals.user === 0` 时应隐藏拆列；KPI 副行已经承载了这个拆分。
- `sourceLabel()` 恰好在 `cataloged === false` 时返回 `—`，也就是给那些**已经带着 已卸载 徽章**的行再放一个破折号 —— 同一个事实的两种编码，而且落在表格最顶部，"来源未知"是更可能的误读。
- `firstAt` 在 payload 里却从不渲染：用户看不到一个技能死了多久，而这恰是"谁不再配得上它的位置"最有用的字段。
- `formatTime` 省略年份，所以一旦面板指向更旧的日志，2024 年的最后一次使用和今年十月无法区分。
- 卡片底内边距是 `2px` 且最后一行的边框被移除，表格渗进卡片下边缘；再多一点底部内边距才收得住这个框。
- KPI 条没有 `aria-live` 包裹，刷新时数字被静默替换。
- 深色渲染里未勾选的复选框是一个实心白方块、读起来像**已勾选** —— 在真实应用里确认宿主是否设置了 `color-scheme: dark` 之前，不要当成缺陷。
- 部分描述尾部的 `\n` 会把一个多余的换行漏进 tooltip；在 payload 落地时统一压一次空白。
- **确实做得好、值得保留**：强调色决策（`state-business-primary` #4176e6，而不是解析成正文色 #0f1115 的 `brand-primary`）；侧栏图标显式取强调色，因为折叠轨会给每一行强制 `label-primary`；`prefers-reduced-motion` 关掉全部过渡；以及被旧构建用 `outline: none` 抹掉、现已恢复的 `:focus-visible` 焦点环（文件内实测 4 处，`outline:none` 0 处）。这些细节让插件读起来像原生 chrome，而不是嵌进来的小组件。

## Questions to Consider
